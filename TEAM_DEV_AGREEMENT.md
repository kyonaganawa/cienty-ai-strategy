# Cienty Development Team Work Agreement

## Purpose

This agreement establishes shared expectations for how our development team works, collaborates, and delivers value. It reflects a strategic decision by Cienty's founders and stakeholders: **using AI-powered tools and coding agents is a core pillar of how we build and ship software**.

This is not optional tooling. It is how we work.

---

## 1. Strategic Context

Cienty operates in a fast-moving market connecting pharmacies with pharmaceutical manufacturers and distributors. Our ability to deliver value to clients faster than the competition is a direct business advantage.

Founders and stakeholders have identified **AI-assisted development as a strategic priority**. We invest in AI tools not as an experiment, but as a deliberate choice to:

- Accelerate the delivery of features and products to clients
- Increase the quality and safety of what we ship
- Enable a small team to operate with the output and reach of a much larger one
- Stay ahead in a rapidly evolving technological landscape

Every team member is expected to align with this direction.

---

## 2. Coding Agents as a Primary Development Tool

We expect the development team to use coding agents (such as Claude Code, Cursor, GitHub Copilot, and similar tools) as a **primary instrument** in day-to-day work. This includes:

- **Creating new projects and features** — Use coding agents to scaffold, implement, and iterate on code. Start with the agent, not from a blank file.
- **Collaborative development** — Work with agents as a pair programming partner. Use them to reason through architecture, review approaches, and explore alternatives before committing to a direction.
- **Testing** — Use agents to generate test cases, increase coverage, identify edge cases, and write both unit and integration tests alongside feature code.
- **Code review and quality** — Leverage agents to review pull requests, spot bugs, identify security issues, and suggest improvements before human review.
- **Monitoring and observability** — Use agents to set up logging, alerting, and monitoring. When incidents occur, use agents to help with root cause analysis and resolution.
- **Safety and security** — Incorporate agents into workflows to audit code for vulnerabilities, validate inputs, review dependencies, and ensure compliance with security best practices.

The goal is not to replace engineering judgment — it is to amplify it. The developer remains responsible for the final output. The agent is the tool that makes that output better and faster.

---

## 3. Proficiency Expectations

Every team member is expected to develop and maintain proficiency in AI-assisted development. This means:

- **Knowing your tools** — Understand how to configure, prompt, and get the most out of the coding agents you use daily. Surface-level usage is not sufficient.
- **Staying current** — AI tools evolve rapidly. Team members should actively follow updates, new capabilities, and changes in the tools we adopt.
- **Prompting effectively** — Writing clear, specific, and context-rich instructions to agents is a skill. Invest in developing it.
- **Understanding limitations** — Know when an agent's output needs deeper review, when to override suggestions, and when a task is better done manually.

---

## 4. Best Practices and Standards

The team collectively defines and maintains best practices for AI-assisted development. These practices are living agreements — they evolve as we learn.

Core principles:

- **Review all agent-generated code** — Never merge agent output without human review. The developer who uses the agent owns the output.
- **Provide context** — Agents perform better with well-structured prompts, project context files (such as CLAUDE.md, .cursorrules), and clear requirements. Invest in maintaining these.
- **Version control discipline** — All work, whether human or agent-generated, follows the same branching, commit, and review standards.
- **Security first** — Agent-generated code must meet the same security standards as hand-written code. Use agents to help enforce this, not to bypass it.
- **Test what you ship** — If an agent writes code, it should also help write the tests. Untested agent output is not ready for review.

---

## 5. Knowledge Sharing and Team Development

Individual expertise benefits everyone. We commit to sharing what we learn:

- **Share what works** — When you discover an effective workflow, prompt pattern, or tool configuration, share it with the team.
- **Share what doesn't** — Failed experiments are just as valuable. Document and discuss what didn't work and why.
- **Contribute to team resources** — Maintain shared prompt libraries, configuration templates, and workflow documentation that the whole team can use.
- **Mentor and support** — Team members with more experience in AI tools should actively help those who are still building proficiency.
- **Participate in team discussions** — Engage in regular discussions about tools, workflows, and practices. This is how we adapt together.

In a landscape where tools and techniques change rapidly, our collective ability to learn and adapt is more valuable than any individual skill.
