The conversation is an illusion

Claude Code holds the history on your machine. Every turn, it stitches the whole thing together and sends a fresh API call. The model sees the entire transcript from scratch each time — it has no recollection between calls.

KEY INSIGHT

Every rule later in this workshop follows from this one fact: if the client has to re-send everything each turn, shorter histories cost less. That's all caching, skills, scripts, and hygiene are doing.

04 · Context

Context windows are working memory

Everything the model "remembers" lives in the window. When it fills up, things break.

200k tokens

Default window. ~500 pages of text. Plenty for most tasks.

1M tokens

Available on Opus 4.6. For very large codebases or long analyses — but expensive and slower.

Bloat signals

Slower responses, forgotten instructions, hallucinated file paths, the model asking for things you already gave it.

04 · Context degradation

Bigger context ≠ better answers

Past a certain point, filling the window doesn't help the model — it hurts it. Instructions get lost, constraints get ignored, responses drift.

Finding one fixed-size instruction
200k window →

The pink needle is the same ~200 tokens in every row. What changes is the haystack around it.

200k cap
20k · early session ~98% recall
80k · mid session ~90% recall
150k · long session ~72% recall
190k · near the cap ~55% recall
NEEDLE AT 20k
1 part in 100
NEEDLE AT 190k
1 part in 950

The instruction is the same — but by the end of a long session, it's ~10× harder to find among everything else the model has to attend to.

your instruction · ~200 tokens · fixed
surrounding history · growing

What degradation looks like in practice

  • Forgets a constraint you set 15 turns ago
  • Re-asks for a file path you already gave
  • Contradicts earlier decisions silently
  • Misses details in the middle of a long file
  • Follows the most recent instruction even if it conflicts with standing rules

Why it happens

Attention is finite. With more tokens to attend to, each one gets a thinner slice. Models are also positionally biased — they recall the start and end of context far better than the middle.

PRACTICAL RULE

Don't judge Claude's response quality by turn 2 of a long session. By turn 40, it's a different (worse) model answering you. When answers start drifting, start a new session — it's almost always faster than fighting a bloated one.

05 · Caching

Prompt caching — the biggest lever

Claude caches the static part of your prompt. If the next turn matches, you pay ~10% of the input cost.

The 1-hour rule

Cache entries live up to 1 hour. Every turn within that window refreshes it. Go idle past it → cache miss → full cost again.

What Claude Code caches for you

  • System prompt
  • CLAUDE.md files
  • Tool definitions
  • Prior conversation turns

Mental model

Think of cache as a warm engine. Keep sending turns → engine stays warm → cheap. Walk away for an hour → engine cools → next turn pays full price to restart.

05 · Anatomy of a prompt

What's in the prompt — and what gets cached

Every turn sends the entire stack. Caching means you only pay full price for the new part at the bottom.

The math

Full prompt size~59,080 tok
Cached portion59,000 tok
Fresh portion80 tok
You pay as if sending~6,000 tok

Why it works

Claude hashes the prefix of your prompt. If the next turn's prefix matches a cached one, Claude reuses the computed state instead of re-processing from scratch.

The cache is re-used if you send another turn within 1 hour.

KEY INSIGHT

The prefix has to match exactly. Change CLAUDE.md, add a tool, or edit an earlier turn → the whole cache from that point down is invalidated.

07 · Your plan

How your subscription actually meters you

You're all on Pro or Max. The cost isn't dollars — it's two overlapping limits and a safety valve.

Limit 1

5-hour rolling window

Every message you send starts (or refreshes) a 5-hour window. Inside that window you get a bucket of usage — hit the cap and you're paused until the window rolls off.

resets continuously · not on the hour

Limit 2

Weekly usage cap

On top of the 5-hour windows, there's a rolling 7-day ceiling. It's the real budget — the 5-hour cap just prevents you from burning the week in an afternoon.

higher on Max · much higher on Max 20x

Safety valve

Extra credits

Hit a limit? You can top up with pay-as-you-go credits to keep going. But these are billed at API rates — noticeably more expensive per token than what your subscription gives you. A safety net, not a plan.

enable in console · set a spend cap

TIP · SPREAD THE LOAD Use your windows — don't burn them

Back-to-back heavy sessions all morning → you hit the 5-hour cap by lunch and sit idle the rest of the day. Spread work across the day so each 5-hour window carries real output. A quick session after lunch keeps the window active without blocking you later.

WHY HYGIENE MATTERS

Every rule in this workshop — caching, skills, scripts, subagents — directly extends your 5-hour window and your week. Good hygiene = more work before the cap, and fewer forced top-ups at API rates.

07 · Model choice

Pick the right model for the job

Same task, three models → wildly different cost, speed, and quality. Default habits leave real money on the table.

Fast & cheap

Haiku 4.5

Cost1×
Speedfastest
Quality ceilinggood

Use for: simple edits, classification, boilerplate, short explanations, pre-filtering before a bigger model.

Balanced default

Sonnet 4.6

Cost~3×
Speedfast
Quality ceilingstrong

Use for: most Claude Code work — refactors, debugging, multi-file changes, reviews, writing. The right default for 80% of sessions.

Heavy reasoning

Opus 4.6

Cost~15×
Speedslower
Quality ceilinghighest

Use for: hard architecture decisions, tricky bugs, long analyses, anything where a bad answer costs more than the model does.

Adjustable effort (extended thinking)

Same model, different thinking budgets. Low effort = quick answer. High effort = the model spends more tokens reasoning internally before responding — better on complex problems, but slower and more expensive.

Treat it like a second dial alongside model choice: Sonnet + high effort often beats Opus + default at a fraction of the cost.

PRACTICAL RULE

Start sessions on Sonnet. Drop to Haiku for grunt work. Escalate to Opus (or turn up effort) only when quality matters enough to pay 5–15× more. Switch models inside Claude Code with /model.

08 · Plan first

For complex tasks, plan before you execute

A wrong turn on a long task burns tokens, limit, and time. Make the agent explain its intent before it starts writing code.

The plan-first workflow
1

Ask for a plan — not execution

"Don't change anything yet. Explain what you'd do, which files you'd touch, and why." Use plan mode (shift+tab) to lock it in.

2

Review & correct the plan

Push back. Catch wrong assumptions. Tighten scope. Iterate until the plan is you-approved — this is the cheapest moment to course-correct.

3

Save the plan as a document

"Write this plan to PLAN.md." A durable artifact — outlives the session, reviewable by a teammate, re-usable if you retry.

4

New session → execute from the plan

Fresh context. Feed in PLAN.md only. The model starts with a clean head and a focused brief — not dragging the whole brainstorm with it.

Why this pays off

Wrong turns on long tasks compound. By the time you notice, 40k tokens of bad direction are in the context — and fixing them means more turns, more tokens, and a more confused agent. A 5-minute plan review prevents an hour of cleanup.

Anti-pattern

"Just do it" on a complex task

You type a one-liner. The agent runs for 20 minutes, edits 14 files, then you realize it misunderstood the requirement. Now the session is bloated, the diff is a mess, and you're paying to unwind it.

RULE OF THUMB

If the task touches > 3 files or takes > 10 minutes to execute, plan first. The planning session itself is cheap — plan mode does no tool calls, no edits, no waste.

14 · Takeaways

Four rules to leave with

If you remember nothing else, remember these.

RULE 01

If raw data > your answer, write a script first

The LLM shouldn't crunch what Python can. Pay once to generate the script, reuse forever.

RULE 02

Every session ends with an artifact

The next session should read it in under 5k tokens. If your handoff needs the full transcript, you didn't finish the session.

RULE 03

Subagents for search, main context for synthesis

Don't pollute the main thread with exploration. Send the messy work out; keep your context clean for the thinking.

RULE 04

Plan mode is free — use it first

Before any session touching >10 files, plan. Alignment upfront costs nothing and saves hours of wrong-direction work.
