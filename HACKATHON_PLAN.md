# Cienty Agent Sprint - Hackathon Plan

> **Status:** Draft for founder approval
> **Format:** 1-day event (Friday)
> **Participants:** ~30 people (all areas)
> **Mode:** Hybrid (in-person + remote)

---

## 1. Overview

**Cienty Agent Sprint** is a one-day internal hackathon where the entire Cienty team forms cross-functional squads to build MVPs and prototypes using AI coding agents (Claude Code, Google AI Studio). The event combines hands-on AI training, team integration, and fast-paced development of projects that matter to Cienty.

### Why now?

- Cienty is betting on agentic AI as a core differentiator. The team needs to **live this culture**, not just build it for customers.
- AI coding agents have matured to a point where non-engineers can build real software. This event proves it.
- Cross-area collaboration unlocks ideas that engineering alone can't see — commercial and CS teams know customer pain points that become the best features.

### Objectives

| # | Objective | How we measure it |
|---|-----------|-------------------|
| 1 | **Train the team on AI coding agents** | Every participant ships code using Claude Code or AI Studio |
| 2 | **Cross-area integration** | Every squad has members from at least 2 different areas |
| 3 | **Build things that matter** | Projects tied to Cienty's roadmap, customers, or operations |
| 4 | **Move fast, learn fast** | Working demos presented at end of day |

## 2. Event Structure

### Schedule

| Time | Activity | Duration | Details |
|------|----------|----------|---------|
| 09:00 | **Opening & Kickoff** | 20 min | Founders set the tone. Why this matters for Cienty. |
| 09:20 | **AI Tools Bootcamp** | 40 min | Hands-on: everyone builds something in 30 min using Claude Code / AI Studio. Live demo + guided exercise. |
| 10:00 | **Squad Formation & Project Selection** | 30 min | Squads pick projects, define scope, assign roles. |
| 10:30 | **Sprint Block 1** | 2h30 | Heads down. Build. Founders circulate giving feedback. |
| 13:00 | **Lunch Break** | 1h | Food + informal networking. Remote team gets delivery vouchers. |
| 14:00 | **Sprint Block 2** | 3h | Continue building. Prepare demo. |
| 17:00 | **Demo Time** | 1h | 5 min per squad: show what you built, how you used AI, what you learned. |
| 18:00 | **Judging & Awards** | 30 min | Founders evaluate. Prizes awarded. |
| 18:30 | **Happy Hour / Closing** | Open | Celebrate. Retro. Talk about what's next. |

**Total active time:** ~8.5 hours (09:00–18:30)

### AI Tools Bootcamp (09:20–10:00)

Since the team already had a Google AI Studio workshop, this session is a **quick warm-up**, not a full course.

**Format:**
1. **5 min** — Brief overview of tools available (Claude Code, Google AI Studio, Cursor)
2. **5 min** — Live demo: building a simple tool from scratch in real-time
3. **25 min** — Hands-on challenge: each person (or pair) builds a micro-project
   - Technical: a CLI tool, a small API, a data script
   - Non-technical: a landing page, a calculator, a form, a dashboard
4. **5 min** — Q&A, tips & tricks for the sprint

**Goal:** Everyone walks out confident they can prompt an AI agent to generate working code.

**Pre-event prep (recommended):** Share a 1-page quick-start guide 2-3 days before the event with tool setup instructions (install Claude Code, create AI Studio account, etc.)

## 3. Squads

### Composition

- **~30 participants** divided into **6 squads of 5 people**
- Each squad must have:
  - At least 1 engineer
  - At least 1 person from commercial, CS, or ops
  - At least 1 person from product, data, or design
- Squads are **pre-assigned by leadership** to ensure balanced mix (not self-selected)

### Roles within each squad

| Role | Who | Responsibility |
|------|-----|----------------|
| **Tech Lead** | Engineer | Architecture decisions, unblocking technical issues |
| **Product Owner** | Commercial / CS / Ops person | Defines scope, prioritizes features, prepares demo |
| **Builders** | Everyone | Everyone codes using AI agents. Engineers mentor non-engineers. |

> **Key rule:** Non-technical members are NOT observers. They build with AI agents alongside engineers. Engineers guide and mentor, not do everything themselves.

### Remote Participation

- Each squad should have a dedicated video call (Google Meet / Discord channel)
- Remote members pair with in-person members via screen sharing
- Use a shared workspace: GitHub repo + real-time collaboration
- Remote participants should be spread across squads (not grouped together)

## 4. Projects

### Project Selection Process

**Timeline:**
1. **2 weeks before** — Leadership shares a list of 10-15 pre-defined project ideas
2. **1 week before** — Team can submit new ideas via a form (Google Forms or Slack thread)
3. **3 days before** — Leadership validates and curates the final project list (~8-10 options)
4. **Day of event** — Squads pick projects (priority order based on random draw)

### Project Requirements

- Must be related to Cienty (product, operations, customers, or team)
- Must be achievable as an MVP/prototype in ~5.5 hours of coding
- Creative and experimental ideas are welcome, as long as there's a Cienty connection
- Must produce a **working demo** (not slides)

## 5. Judging

### Judges

**Founders** are the primary judges, supported by peer feedback.

### Evaluation Criteria

| Criteria | Weight | Description |
|----------|--------|-------------|
| **Impact** | 30% | How valuable is this for Cienty? Would we actually use or ship this? |
| **Execution & Maturity** | 25% | How complete and polished is the prototype? Does it work? |
| **AI Agent Usage** | 20% | How effectively did the squad leverage AI coding agents? |
| **Creativity** | 15% | Originality of the idea or approach. Surprises welcome. |
| **Teamwork** | 10% | Did the whole squad contribute? Evidence of cross-area collaboration. |

### Demo Format

- **5 minutes** per squad (strict timer)
- Structure: Problem → Solution → Live Demo → AI Usage Highlights → Learnings
- All squad members should participate in the presentation
- Q&A from founders (2 min)

### Technical Setup

- [ ] Create a GitHub org/repo for hackathon projects (1 repo per squad or monorepo with folders)
- [ ] Ensure all participants have Claude Code installed (or access to web-based alternatives)
- [ ] Ensure all participants have Google AI Studio access

### Remote Experience

To avoid remote participants feeling like second-class citizens:

- **Dedicated Squad Calls** — Each squad keeps a video call open all day
- **Delivery Vouchers** — Remote team gets iFood vouchers for lunch
- **Equal Demo Time** — Remote squads present via screen share with same time allocation
- **Buddy System** — Each remote person has an in-person buddy who keeps them looped in

## 9. Rules

1. **All code must be written during the event** — no pre-built projects
2. **AI coding agents must be used** — this is the whole point. Manual coding is allowed but AI agents should be the primary tool
3. **Open source libraries and APIs are allowed** — use whatever tools accelerate your build
4. **Every squad member must contribute** — everyone codes, everyone presents
5. **Respect the clock** — demos start at 17:00 sharp, no extensions
6. **Have fun** — this is about learning and building together, not stress
7. **Ask for help** — founders and senior engineers circulate all day. Don't stay stuck for more than 15 minutes.

## 10. Post-Event

### Same Day
- Announce winners and celebrate
- Quick retro question to all (Google Form): "What was the best part? What would you improve?"

### Week After
- Leadership reviews all projects with product team
- Decide which 1-2 projects to continue developing
- Share internal post with photos, demos, and learnings
- Update AI training roadmap based on what the team learned

### Long-term
- Make this a **recurring event** (quarterly or bi-annual)
- Build an internal "innovation pipeline" where hackathon ideas graduate to product
- Track how team AI proficiency evolves over time
