# Cienty Development Team Work Agreement

## Purpose

This agreement describes how we collaborate as a development team to deliver value, learn quickly, and continuously improve.

At Cienty, we believe AI-powered tools and coding agents are an important part of how we build software. We use them to increase speed, quality, and focus — while keeping human judgment, responsibility, and teamwork at the center.

---

## 1. Strategic Context

Cienty operates in a fast-moving market connecting pharmacies with pharmaceutical manufacturers and distributors. Delivering value to clients quickly and reliably is a core business advantage.

To support this, founders and stakeholders have prioritized AI-assisted development as a strategic capability. We invest in AI tools to help us:

- Deliver features and products faster
- Improve quality and reliability
- Expand the impact of a small, high-performing team
- Adapt quickly in a rapidly evolving technology landscape

With these agreements in place, the company expects measurable operational gains: each sprint should deliver more meaningful output, tasks should move from implementation to deployment in less time, and we should test and experiment more frequently to accelerate learning.

We expect everyone on the team to engage with this direction and help shape how we apply it effectively.

---

## 2. Coding Agents in Day-to-Day Development

We encourage the team to use coding agents (such as Claude Code, Cursor, GitHub Copilot, and similar tools) as a default partner in daily work, including:

- **Creating new projects and features** — Use agents to scaffold, implement, and iterate.
- **Collaborative development** — Use agents to explore architecture, compare approaches, and reason through tradeoffs.
- **Testing** — Use agents to draft test cases, improve coverage, and identify edge cases.
- **Code review and quality** — Use agents for pre-review checks, bug discovery, and improvement suggestions.
- **Monitoring and observability** — Use agents to support logging, alerting, and incident analysis.
- **Safety and security** — Use agents to review dependencies, detect risks, and strengthen secure coding practices.

Our goal is not to replace engineering judgment, but to amplify it. Developers remain accountable for final decisions and shipped code.

---

## 3. Proficiency, Learning, and Growth

We treat AI-assisted development as a professional skill we build together over time.

Each team member is expected to:

- **Build tool fluency** — Learn configuration, workflows, and effective usage patterns.
- **Stay current** — Follow relevant updates and share useful changes with the team.
- **Prompt effectively** — Write clear, specific, context-rich instructions.
- **Use critical thinking** — Validate outputs, identify limitations, and choose manual approaches when appropriate.

To support continuous growth, we commit to creating space for experimentation, reflection, and skill development.

---

## 4. Working Standards and Good Practices

Our standards apply equally to human-written and agent-assisted work.

Core principles:

- **Human review is required** — All agent-generated code must be reviewed before merge.
- **Context improves outcomes** — Maintain strong project context files (e.g., `CLAUDE.md`, `.cursorrules`) and clear requirements.
- **Version control discipline** — Follow shared branching, commit, and PR review practices.
- **Security by default** — Apply security standards consistently and use agents to strengthen compliance.
- **Test what we ship** — Code and tests should evolve together.

These standards are living practices and will be updated as we learn what works best.

---

## 5. Knowledge Sharing and Continuous Improvement

We improve faster when we learn together.

Team commitments:

- **Share effective workflows** — Document useful prompts, patterns, and tool configurations.
- **Share lessons from failures** — Discuss what didn’t work and why, without blame.
- **Contribute to shared resources** — Maintain prompt libraries, templates, and workflow docs.
- **Support each other** — Experienced members mentor peers building AI proficiency.
- **Participate in regular reviews** — Reflect on tools, outcomes, and process improvements as a team.

We also encourage experimentation by recognizing and rewarding contributions that improve team capability, quality, and delivery.

## Agreement

This document represents a shared understanding between Cienty’s leadership and development team. It is reviewed regularly and updated as our strategy, tools, and practices evolve.
